## Описание работы

В данной лабораторной работе реализован REST API для системы онлайн-бронирования отелей. Приложение позволяет управлять пользователями, отелями, номерами, бронированиями, отзывами и платежами. Особое внимание уделено архитектуре приложения, безопасности с JWT-аутентификацией, тестированию и настройке CI/CD с автоматическим AI-код-ревью.

Проект построен по классической слоистой архитектуре с чётким разделением ответственности: API-слой (FastAPI роутеры), сервисный слой (бизнес-логика), слой доступа к данным (репозитории) и модели SQLAlchemy. Зависимости инжектируются через механизм `Depends` в FastAPI, что обеспечивает гибкость и тестируемость.

## Выполненные задания

### Задание 1: Реализация REST API приложения

Разработана полная система бронирования отелей со следующими компонентами:

*   **ORM-модели** (`app/models/`):
    *   `User` — пользователи системы с ролями (admin, user).
    *   `Hotel` — отели с названием, описанием, местоположением и рейтингом.
    *   `Room` — номера в отелях с типом, ценой и доступностью.
    *   `Booking` — бронирования с датами заезда/выезда, статусами и итоговой стоимостью.
    *   `Review` — отзывы пользователей с оценкой и комментарием.
    *   `Payment` — платежи с суммой, статусом и связью с бронированием.
    *   Все модели используют современный стиль SQLAlchemy 2.0 с `Mapped[]` и аннотациями типов.

*   **Repository Pattern** (`app/repositories/`):
    *   Реализован изолированный слой для работы с базой данных через асинхронные CRUD-операции.
    *   Каждый репозиторий отвечает только за свою модель, что упрощает поддержку и тестирование.

*   **Service Layer** (`app/services/`):
    *   Бизнес-логика вынесена в отдельные сервисы: проверка доступности номеров, расчёт стоимости бронирования, автоматический пересчёт рейтинга отеля при добавлении отзыва.
    *   Реализована аналитика для администраторов: общая статистика, прибыль за 30 дней, загрузка номеров, топ-5 отелей.
    *   Сервисы не зависят от HTTP, что позволяет переиспользовать их в разных контекстах.

*   **Pydantic v2 схемы** (`app/schemas/`):
    *   Валидация входящих запросов и форматирование ответов с помощью современных возможностей Pydantic.
    *   Настроены валидаторы: проверка формата email, ограничение рейтинга 1–5, положительная цена номера.
    *   Используются вычисляемые поля (`@computed_field`) для денормализованных данных из связей.

*   **API роутеры** (`app/api/v1/`):
    *   Эндпоинты для аутентификации, управления отелями, номерами, бронированиями, отзывами и админ-аналитики.
    *   Реализован ролевой доступ через кастомные зависимости `get_current_user()` и `get_current_admin()`.
    *   Полная интерактивная документация доступна через Swagger UI (`/docs`) и ReDoc (`/redoc`).

### Задание 4: Настройка CI/CD

Автоматизированы процессы проверки качества кода через GitHub Actions (`.github/workflows/`):

*   **`ci.yml`** — Continuous Integration:
    *   **Линтинг и проверка типов**: `ruff` для стиля и импортов, `mypy` для статической типизации.
    *   **Тестирование**: запуск тестов с `pytest --cov` и отчётом о покрытии.
    *   **Проверка безопасности**: сканирование зависимостей на известные уязвимости.
    *   **Сборка Docker-образа**: проверка, что приложение успешно контейнеризуется.

*   **`pr-ai-review.yml`** — AI Code Review:
    *   При создании или обновлении Pull Request автоматически запускается анализ изменений.
    *   Git diff отправляется в AI-модель (Google Gemini), которая выполняет код-ревью.
    *   Результаты публикуются в виде комментария к PR с категоризацией замечаний (баги, безопасность, хорошие практики).

### Задание 7: Модульное и интеграционное тестирование

Разработан комплексный набор тестов с использованием `pytest` и `pytest-asyncio`:

*   **Изолированное тестовое окружение**:
    *   Каждый тест работает со свежей in-memory базой данных SQLite, что гарантирует независимость и воспроизводимость.
    *   Тестовые фикстуры автоматически создают необходимых пользователей и данные.

*   **Покрытие основных сценариев**:
    *   Регистрация и аутентификация пользователей (включая невалидные токены).
    *   CRUD-операции с отелями и номерами (с проверкой прав доступа).
    *   Бронирование номеров (включая проверку доступности и конфликт дат).
    *   Отзывы с автоматическим пересчётом рейтинга отеля.
    *   Аналитика для администраторов (статистика, прибыль, топ отелей).
    *   Граничные случаи: повторное бронирование, отмена, невалидные данные.

*   **Конфигурация тестов** (`pytest.ini`):
    *   Настроен асинхронный режим (`asyncio_mode = auto`).
    *   Определены маркеры для разделения тестов по модулям.
