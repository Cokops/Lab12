## [16] Исправление ошибки импорта Base в main.py

Обнаружена и устранена критическая ошибка при запуске приложения:

- **Ошибка**: `ImportError: cannot import name 'Base' from 'app.models'`
- **Причина**: В файле `app/main.py` производился импорт `Base` из `app.models`, но `Base` не экспортировался из этого модуля. `Base` определен в `app/database.py` как `declarative_base()`.
- **Решение**:
  1. В файле `app/main.py` изменен импорт с `from app.models import Base` на `from app.database import Base`.
  2. Убедился, что `engine` также импортирован из `app/database.py`.
  3. Добавлен комментарий о том, что для продакшена следует использовать миграции Alembic.


Теперь приложение должно запуститься без ошибок импорта. Все модели корректно зарегистрированы в `Base`, так как они импортируются в `app/models/__init__.py`, и `Base.metadata.create_all(bind=engine)` сможет создать все таблицы в базе данных.

## [17] Исправление ошибки синхронного DDL на асинхронном движке

Обнаружена и устранена критическая ошибка при запуске приложения:

- **Ошибка**: `'AsyncEngine' object has no attribute '_run_ddl_visitor'`
- **Причина**: Попытка выполнить синхронную операцию `Base.metadata.create_all(bind=engine)` на асинхронном движке (`AsyncEngine`). SQLAlchemy 2.0 требует использовать асинхронные методы для асинхронных движков.
- **Решение**:
  1. Удалено синхронное создание таблиц `Base.metadata.create_all(bind=engine)` из файла `app/main.py`.
  2. Приложение теперь не создаёт таблиц при каждом запуске.


**Рекомендация**: Для управления схемой базы данных в продакшене необходимо использовать систему миграций Alembic. Удаление этой строки — это правильный шаг, так как миграции обеспечивают контроль версий схемы и безопасное развёртывание изменений.

Документация в `PROMPT_LOG.md` была обновлена, в неё добавлен раздел [17], описывающий эту ошибку и её решение. Приложение должно запуститься успешно.
