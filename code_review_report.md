# Отчёт по Code Review

Ниже представлены найденные проблемы в сгенерированном коде и способы их исправления.

## 1. Неправильный URL для OAuth2 в схеме токена

**Что сгенерировал ИИ:**
```python
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="api/v1/auth/login")
```

**В чём проблема:**
Относительный путь `api/v1/auth/login` без начального слеша может привести к неправильной работе маршрутизации в FastAPI, особенно при использовании подключаемых роутеров. Корректный путь должен начинаться с `/`.

**Как исправил:**
Изменил на абсолютный путь:
```python
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/v1/auth/login")
```

## 2. Жёстко прописанный SECRET_KEY в коде

**Что сгенерировал ИИ:**
```python
SECRET_KEY: str = "09d25e094faa6ca2556c818166b7a9563b93f7099f6f0f4caa6cf63b88e8d3e7"
```

**В чём проблема:**
Хранение секретного ключа JWT прямо в коде представляет серьёзную уязвимость безопасности. При попадании кода в публичный репозиторий это позволяет злоумышленнику подписывать и расшифровывать токены.

**Как исправил:**
Заменил значение на заглушку и добавил переменную в файл `.env`, который должен игнорироваться git'ом. В продакшене ключ должен задаваться через переменные окружения.

## 3. Дублирование проверки существующего пользователя

**Что сгенерировал ИИ:**
```python
if existing_user:
    return None  # ...
if existing_user:
    raise HTTPException(...)
```

**В чём проблема:**
Дублирование условия `if existing_user` после попытки вернуть `None`. Это ошибка логики, которая делает часть кода недостижимой, и приводит к неопределённому поведению.

**Как исправил:**
Удалил лишнюю строку `return None`, оставив только выброс исключения, так как в текущей архитектуре исключения обрабатываются корректно.

## 4. Уязвимость при работе с базой данных (SQLite в продакшене)

**Что сгенерировал ИИ:**
```python
DATABASE_URL: str = "sqlite+aiosqlite:///./test_hotel_booking.db"
```

**В чём проблема:**
Использование SQLite в асинхронном приложении не рекомендуется для продакшена. Кроме того, использование тестовой БД в продакшене может привести к потере данных. Также в комментарии указано, что не установился `asyncpg`, что указывает на проблему с зависимостями.

**Как исправил:**
Добавил в `.env` переменную `DATABASE_URL`, чтобы можно было легко переключаться между средами. Рекомендовано использовать PostgreSQL с `asyncpg` в продакшене.

## 5. Неконсистентная обработка логики в `register_user`

**Что сгенерировал ИИ:**
Попытка вернуть `None` при существовании пользователя, но затем выброс исключения.

**В чём проблема:**
Смешение стилей обработки ошибок: возврат `None` и выброс исключения. Это вводит в заблуждение вызывающий код и нарушает принцип единого стиля.

**Как исправил:**
Удалил строку с `return None`, оставив только `raise HTTPException`, так как это соответствует стилю FastAPI и обеспечивает единообразие с другими частями API.
